# AdPilot

Автономный агент, который сам ведёт рекламные кампании в стиле Яндекс Директа.

На каждом тике агент забирает статистику и считает ключевые метрики. По ним он решает, что делать со ставками и бюджетами, а каждое решение записывает в журнал с причиной и цифрами.

---

## Как это работает

1. **Сбор статистики.** Агент получает показы, клики, заказы и расход по каждой кампании.
2. **Расчёт метрик.** Метрики всегда считает код:
   - **CPC** — цена клика (расход / клики)
   - **CPM** — цена тысячи показов (расход / показы × 1000)
   - **CTR** — кликабельность (клики / показы)
   - **CR** — конверсия в заказ (заказы / клики)
   - **CPO** — цена заказа (расход / заказы)

   Если кликов или заказов нет, метрика помечается как «нет данных».
3. **Решение.** Движок выбирает действие: подождать данных, снизить или повысить ставку, изменить бюджет, поставить на паузу или ничего не менять.
4. **Проверка ограничений.** Решение проверяется по заданным лимитам. Неподходящее решение отклоняется, и кампания остаётся без изменений.
5. **Журнал и применение.** Решение записывается в журнал и только после этого применяется. Изменения без записи в журнале не выполняются.

Время в симуляции идёт по таймеру или по кнопке «один тик».

---

## Движки принятия решений

| Движок  | Как решает                                                                                                                          |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `rules` | Набор правил с настраиваемыми порогами                                                                                              |
| `llm`   | Языковая модель Yandex AI Studio. Получает готовые метрики, цели и лимиты и возвращает действие, значение и причину по строгой схеме |

Движок переключается в настройках. На одних и тех же данных можно сравнить, что решил бы каждый из них.

---

## Ограничения (guardrails)

- Максимальное изменение ставки и бюджета за один шаг
- Потолок дневного бюджета
- Минимальный объём данных, без которого решение не принимается
- Пауза между изменениями одной кампании
- Проверка ответа модели: неизвестное действие, значение за пределами лимита или невалидный ответ отклоняются, а отказ записывается в журнал
- **Dry-run:** агент пишет в журнал, что сделал бы, но ничего не меняет

---

## Журнал решений

В каждой записи журнала есть:

- время и номер тика
- кампания и движок
- действие и значения «было / стало»
- причина
- метрики на момент решения
- признак dry-run
- результат проверки: принято или отклонено
- исходный ответ модели (для движка `llm`)

В журнал можно только добавлять записи. Редактировать или удалять их из интерфейса нельзя.

---

## Симулятор кабинета

Агент работает с реалистичным симулятором рекламного кабинета:

- У каждой кампании есть скрытые параметры: CTR, конверсия и чувствительность к ставке. Агенту они недоступны.
- Показы зависят от ставки и остатка дневного бюджета. Клики и заказы генерируются случайно по скрытым параметрам.
- Прогон воспроизводим: при том же seed результат будет тем же.
- Готовый набор кампаний: «хорошая», «плохая», «новая» (мало данных) и «капризная» (качество падает в середине прогона).

Агент обращается к кабинету через общий интерфейс. Поэтому симулятор можно заменить подключением к песочнице Яндекс Директа.

## Веб-панель

| Страница          | Что показывает                                                       |
| ----------------- | -------------------------------------------------------------------- |
| `/dashboard`      | Сводка: расход, заказы, CPO по кампаниям, последние решения          |
| `/campaigns`      | Список кампаний: ставка, бюджет, метрики                             |
| `/campaigns/[id]` | Графики кампании по тикам (ставка, расход, CPO) и её журнал          |
| `/journal`        | Журнал решений с фильтрами по кампании, действию и движку           |
| `/settings`       | Правила, пороги, лимиты, dry-run, выбор движка, параметры модели     |
| `/simulator`      | Управление симулятором: один тик, сброс с выбором seed               |

Доступ к панели есть только у администратора. Вход по email и паролю.

## Технологии

Next.js, TypeScript, PostgreSQL + Prisma, Auth.js, Tailwind CSS + shadcn/ui, Yandex AI Studio. Сервисы web, worker и db запускаются через Docker Compose.
